# 배포 — 우리 학교 주소 만들기

[Vercel](https://vercel.com/) Hobby(무료) 요금제로 `https://<이름>.vercel.app/` 주소를 만듭니다. 방문자는 계정 없이 접속하며, 사이트는 이름·성적·계정 정보를 모으지 않고 브라우저 안에서 돌아갑니다. 방명록은 [시트 연결](시트-연결.md)의 Google 시트에만 저장됩니다.

## 방법 1 — GitHub와 연결하기 (가장 쉬움)

1. Vercel에 GitHub 계정으로 로그인하고 **Add New → Project**에서 내 저장소를 고릅니다.
2. 설정은 저장소의 `vercel.json`을 그대로 씁니다. 설치 `npm ci`, 빌드 `npm test && npm run build`, 출력 폴더 `dist`입니다. 검사가 실패하면 배포되지 않습니다.
3. **Deploy**를 누릅니다. 이후 `main`에 반영할 때마다 자동으로 다시 배포됩니다.
4. 나온 주소를 `src/school-config.ts`의 `siteUrl`에 적고 다시 반영합니다. 카카오톡 공유 미리보기 이미지가 이 주소를 씁니다.

## 방법 2 — 명령으로 직접 올리기

자동 배포 없이 검토를 마친 버전만 올리고 싶을 때입니다.

```bash
npm i -g vercel
```

```bash
vercel login
```

작업 폴더에서 바로 올리지 말고, 커밋된 파일만 담은 사본에서 올립니다. 작업 폴더의 `references/`처럼 Git이 추적하지 않는 큰 자료가 함께 올라가면 Vercel의 파일당 100MB 제한에 걸리거나 원본 자료가 새어 나갈 수 있습니다. `.vercelignore`가 주요 자료를 막지만, 사본에서 올리는 편이 확실합니다.

```bash
DEPLOY_DIR="$(mktemp -d)" && git archive main | tar -x -C "$DEPLOY_DIR" && (cd "$DEPLOY_DIR" && vercel deploy --prod --yes)
```

처음 실행하면 Vercel이 프로젝트 이름을 묻습니다. 그 이름이 주소(`<이름>.vercel.app`)가 됩니다.

## 공개 전에 확인할 것

- [ ] `npm run check`, `npm test`, `npm run build`가 모두 통과한다.
- [ ] `src/school-config.ts`의 학교 이름·`siteUrl`·`dataUrl`이 우리 학교 값이다.
- [ ] `references/`의 원본 자료, 학생 사진, 도면 이미지가 저장소와 `dist/`에 없다.
- [ ] 휴대폰과 PC에서 교문 출발 → 현관 → 교실까지 걸어 봤다.
- [ ] 카카오톡으로 주소를 보내 공유 미리보기 제목·이미지를 확인했다. 예전 미리보기가 남으면 [카카오 OG 캐시 초기화](https://developers.kakao.com/tool/clear/og)를 씁니다.

## 되돌리기

Vercel 대시보드의 **Deployments**에서 이전 배포를 고르고 **Promote to Production**(또는 **Instant Rollback**)을 누르면 이전 버전으로 돌아갑니다.
